# RED BRIDGE DEV — Icon Design Guide

디자이너에게 전달하기 위한 아이콘 제작 가이드. 아이콘 20개(3개 섹션 × 6–7개) 커스텀 세트 제작을 위한 사양서입니다.

---

## 1. 프로젝트 개요

- **서비스명**: RED BRIDGE DEV (레드 브릿지 데브)
- **분야**: 웹/앱/솔루션 외주 개발 (B2B)
- **브랜드 컨셉**: 고객과 기술을 "안전하고 튼튼하게 연결하는 다리(Bridge)"
- **웹사이트 톤**: 다크 모드 기본 · 빨강 액센트 · Liquid Glass (유리 질감) · 시네마틱
- **현재 상태**: Phosphor Duotone 스톡 아이콘 사용 중 — 브랜드 고유성 부족으로 커스텀 세트 제작

---

## 2. 브랜드 방향성

### 전달해야 할 인상
| 키워드 | 의미 |
|---|---|
| **정밀(Precision)** | 엔지니어링 품질 — 수학적 그리드, 픽셀 단위 정렬 |
| **견고(Solid)** | 브릿지 메타포 — 구조적, 무너지지 않는 느낌 |
| **현대(Modern)** | 2026년 감각 — 둥근 끝맺음, 여유 있는 여백 |
| **다리(Bridge)** | 연결의 시각적 힌트 — 모든 아이콘에 미묘한 "연결" 모티프 가능 |

### 피해야 할 느낌
- 손글씨/스케치 느낌 (너무 캐주얼)
- 과도한 디테일 (작은 사이즈에서 뭉개짐)
- 3D 입체/그라데이션 과다 (평면 디자인 기조 유지)
- 지나치게 귀여운 마스코트 스타일

---

## 3. 디자인 원칙

### 3.1 스타일 (Style)
- **베이스**: 지오메트릭 라인 아이콘 (geometric line art)
- **fill 처리**: Duotone — 주요 형태는 선(stroke), 강조 부위는 면(fill)
- **성격**: 라인 80% + 필 20% 비율 권장 — 깨끗한 선 베이스에 한 두 군데 붉은 점/면 강조

### 3.2 기하학 (Geometry)
- **그리드**: 24×24 또는 32×32 정사각형 기본 격자
- **Keyline 가이드**: 20×20 원(circle), 18×18 정사각(square), 16×20 세로 직사각(rect) — 이 Keyline 안에 주요 형태 배치
- **좌우 여백(padding)**: viewBox 기준 2px (24px일 때)

### 3.3 선 (Stroke)
- **두께**: **1.75px** (24×24 viewBox 기준) — 고정
- **끝맺음**: `stroke-linecap: round`, `stroke-linejoin: round`
- **직선 · 곡선**: 45° · 90° 각도 우선, 자유곡선 최소화
- **모서리 radius**: 외곽은 `2px`, 내부 각진 요소는 `1px`

### 3.4 색상 사용 (Color)
- **주 선색**: `currentColor` — 자동으로 사이트 텍스트 색과 일치 (흰색/검정)
- **액센트 색**: `#DC2626` (red-600) — 각 아이콘에 **정확히 1곳** 적용
  - 적용 예: 화면 중앙 점, 코너 하이라이트, 브릿지 상판 중간 지점
- **duotone 보조톤**: 주 선색의 **30% opacity** — 면(fill) 처리되는 영역

---

## 4. 기술 사양 (Technical)

### 4.1 파일 형식
- **SVG** 단일 파일, 최적화(SVGO 처리) 후 전달
- **viewBox**: `0 0 24 24`
- **fill/stroke**: 하드코딩 색상 사용 금지 → `currentColor`, `#DC2626` (액센트) 2가지만 허용
- **width/height**: SVG 태그에 고정 크기 **미지정** (CSS로 제어)

### 4.2 네이밍 규칙
```
rbd-{section}-{concept}.svg

예:
rbd-service-web.svg
rbd-service-app.svg
rbd-process-consultation.svg
rbd-value-stability.svg
```

### 4.3 반응 상태 (선택적 확장)
아이콘별 **2가지 변형** 제공 권장:
- `default` — 기본 상태
- `active` — 호버/활성 상태 (선 두께 동일하게 유지, 액센트 영역 확장)

## 5. 아이콘 리스트 (Per-section)

### Tier 1 · Process (7개) — 최우선

가장 오래 노출되는 섹션(pin + horizontal scrub). 각 단계는 서사를 이루므로 연속성 있는 디자인 필요.

| # | Step | 현재 아이콘 | 컨셉 방향 |
|---|---|---|---|
| 01 | 상담 & 분석 | ChatCircleText | 말풍선 + 안에 점 3개 또는 돋보기. 대화 시작 의미 |
| 02 | 기획 & 설계 | FileText | 겹쳐진 문서 + 체크 마크 또는 그리드. 설계도 느낌 |
| 03 | 디자인 | Palette | 팔레트 + 원형 컬러 3개. 그 중 하나가 red 액센트 |
| 04 | 개발 | Code | 꺾쇠 `< >` + 중앙에 red 코드 라인. 타이핑 커서 느낌 |
| 05 | 테스트 & QA | TestTube | 플라스크 + 안에 점 또는 체크마크. 검증 뉘앙스 |
| 06 | 배포 & 런칭 | RocketLaunch | 로켓 + 아래 방사형 화염선. 런칭 |
| 07 | 유지보수 | Headphones | 헤드셋 + 중앙에 맥박선 또는 기어. 지속 지원 |

**공통 모티프 제안**: 각 아이콘 우상단에 **작은 원형 red 점**을 공통으로 넣어 "단계 번호" 시각화 → 7개가 나란히 있을 때 하나의 세트로 읽힘.

---

### Tier 2 · Services (6개)

| # | Service | 현재 아이콘 | 컨셉 방향 |
|---|---|---|---|
| 1 | 웹 개발 | Globe | 격자가 그려진 구(globe) + 한 점 red. 경위선 명시 |
| 2 | 앱 개발 | DeviceMobile | 모바일 윤곽 + 내부 작은 UI 힌트(카드 3개) |
| 3 | 백엔드 개발 | HardDrives | 가로 막대 3개 스택 + 맨 위에 red 표시등 |
| 4 | 데이터베이스 | Database | 실린더 3단 + 가장 아래에 red 흐름선 |
| 5 | 클라우드 인프라 | Cloud | 구름 윤곽 + 내부에 서버 막대 2개, red 연결선 |
| 6 | 솔루션 개발 | Gear | 기어 + 중앙에 작은 화살표 순환, 한 톱니에 red |

**공통 모티프 제안**: 아이콘 테두리를 `rounded-square` 컨테이너로 감싸지 **않고** 독립된 실루엣으로. (현재 코드가 이미 red-gradient 박스를 backplate로 쓰기 때문에 아이콘 자체는 깨끗해야 함)

---

### Tier 3 · About Values (6개)

| # | Value | 현재 아이콘 | 컨셉 방향 |
|---|---|---|---|
| 1 | 안정성 | ShieldCheck | 방패 + 내부에 브릿지 상판 모티프 또는 체크. "견고" |
| 2 | 확장성 | Lightning | 번개 or 위로 뻗는 3개 선 계단. "성장" |
| 3 | 협업 | Users | 사람 3명 실루엣이 아닌, **연결된 점 3개 + 선**. "네트워크" |
| 4 | 목표 지향 | Target | 과녁 + 중앙에 red 점, 바깥 원은 opacity 감소 |
| 5 | 기술 전문성 | Code | `</>` + 중앙에 별(star) or 인증 배지. "전문가" |
| 6 | 체계적 프로세스 | StackSimple | 쌓인 레이어 4단 + 우측에 흐름 화살표 |

**공통 모티프 제안**: About은 "우리의 철학"이므로 Services/Process와 시각적으로 구분되게 — **내부 여백을 더 주고**, 모티프를 미니멀하게.

## 6. 시그니처 요소 (Brand Signature)

모든 아이콘에 **1가지 브랜드 시그니처** 삽입 권장:

### 옵션 A · "브릿지 스팬" 선
- 아이콘 어딘가에 양 끝을 연결하는 **가로 선 1개** 숨겨 놓기 (0.5~1px)
- 예: Process 단계마다 하단에 미세한 연결선 — 순서대로 놓으면 긴 다리가 이어지는 착시

### 옵션 B · "Red Dot"
- 모든 아이콘에 정확히 **1개의 red 원형 점** (1.5px diameter)
- 위치는 아이콘마다 다르되, "중심/코너/끝점" 중 하나에서 의미 있는 자리

**제 추천**: 옵션 B (Red Dot) — 20개 세트 전체에 통일감, 관리 쉬움, 첫인상 확 꽂힘

## 7. 제작 우선순위 & 공수

| Tier | 섹션 | 개수 | 예상 공수 (숙련 디자이너) |
|---|---|---|---|
| 1 | Process | 7 | 2–3일 |
| 2 | Services | 6 | 1.5–2일 |
| 3 | About Values | 6 | 1.5–2일 |
| **합계** | | **19** | **5–7일** |

**단계적 제작 권장**: Tier 1만 먼저 → 결과 확인 → Tier 2, 3 확정 (처음 7개에서 공통 원칙 굳힌 후 나머지 확장)

---

## 8. 제작 후 전달물 (Deliverables)

1. **SVG 원본** (최적화 전)
2. **SVG 최적화본** (SVGO 처리, fill/stroke가 `currentColor`·`#DC2626`로만 구성)
3. **PNG 미리보기** (64px, 흰/검 배경 각각)
4. **Figma 원본 파일** (편집/수정 가능하게)
5. **네이밍**: `rbd-{section}-{concept}.svg` 규칙 준수

디자인 프로세스 중 **48/64/128px로 축소 검사** 필수. 작은 사이즈에서 뭉개지면 리파인.

## 9. 레퍼런스

참고하면 좋을 아이콘 세트 (스타일 방향 · 복제 금지):
- **Linear app** icon system — 명료한 라인 + 최소 액센트
- **Stripe** docs 아이콘 — duotone 처리의 정석
- **Vercel / Geist** 아이콘 — 지오메트릭 정밀도
- **Radix Icons** — 24×24 그리드 활용법
- **Phosphor Duotone** — 현재 우리가 쓰는 스타일, 이보다 한 단계 브랜드화된 결과물 목표
